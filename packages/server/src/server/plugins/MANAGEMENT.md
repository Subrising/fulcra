# Bundled controller integration

The host owns management authentication. A successful bearer admission attaches a principal to that physical socket. Paired-device and protected-local-IPC embedders pass validated `SessionAdmission.authentication`; an address, client ID, service session or owner permission array is insufficient. On resumption each socket is admitted separately. Disconnect removes that socket's evidence and closes its invocations.

Trusted synchronous setup registers `server.managementBridge.register(handler)` for `orca-organization-next`. Distribution startup supplies `{enabled(target), validate}` to `initializeTrustedPlugins` / `loadTrustedPlugins`; there is no public configuration mutator. `enabled(target)` must reflect live readiness of the verified bundled runtime instance and bridge. The loader records canonical distribution directories outside PASEO_HOME; the runtime accepts a trusted-claimed ID only from that directory, checks entry realpaths, and binds authority to the currently loaded object. Ordinary install, enable and ID override cannot claim those IDs. `validate` must use the controller's existing method/input schemas and reject unknown methods or unsupported fields. Missing configuration refuses all management contexts. This product tree does not carry those controller business schemas.

A handler receives `ctx.management` only for an authenticated, permitted caller. Use `ctx.management.invoke({method,input})` per request; never cache the context. The host keeps the principal and permission reader, accepts no returning principal, enforces one-use call IDs and a command-bound write fence, and revokes authority on settlement, disconnect and shutdown. There are 32 calls and a 30-second deadline per invocation.

V4 constructs `ControllerChannel` only after validating the owned child and completing its boot/contract/epoch handshake. Its callbacks must use the trusted contribution's `issueProvenance` and `trustedPlugins.revokeProvenance("orca-organization-next")`, and the plugin-bound `createControllerRpcProxy` for daemon RPC. Wire child close/error, disable and shutdown to `channel.close()`/`crash()` before replacement. Wire the bridge to `channel.management`. The host creates and immediately consumes its command digest record before bridge entry; the effective one-use capability is the asynchronous-scope write fence. The channel consumes that fence, rechecks the invocation after any bridge await. Child command replies must carry the matching command ID and current epoch. IDs remain tombstoned for the epoch; a full bounded history refuses until a fresh channel is established.

The channel is an adapter, not a process supervisor. Process creation, verified bundle identity, readiness handshake, filesystem roots and owned lock/socket recovery remain V4 responsibilities. No daemon password is read or passed to the controller.

A resumed socket retains only its own admission grants, intersected with current Session permissions. A newly granted permission requires fresh admission; revocation applies immediately to existing invocations. An authentication identity must match the admission principal. Failed trusted setup closes the bridge.

Controller client code can use `DaemonClient.invokeRawInput(message, responseType)` to preserve `inputProvenance` and receive a correlated reply without reaching private transport internals. The daemon still validates and consumes the provenance; the method grants no authority itself.

## Known limits and V4 obligations

- The paired-device producer must verify the pairing key per socket and attach that device's grant permissions, never `OWNER_PERMISSIONS`. Acceptance must prove that an existing limited grant stays limited, including when resuming an owner Session. Device revocation must close sockets or replace permissions. Protected-local-IPC evidence must come from an embedding-host channel, not a loopback address or socket-path name.
- V4's bridge must be a stable forwarder to the current channel. On close/crash the transport must reject pending sends as **uncertain** if a write may have occurred; never report a possibly executed command as refused or automatically replay it.
- V3 read-only handlers never call `invoke`; caches contain data only. Bridge effects stay in the child and use the attributed daemon-RPC proxy, not direct host mutation in a human RPC scope.
- The complete JSON envelope is depth 1; the deepest scalar or container may be at depth 32, and depth 33 is refused. Invalid frames produce generic errors without parser details. A safe bounded id/epoch allows an `invalid`, `expired`, `unauthorised` or `unavailable` reply; malformed/oversized envelopes have no safe reply identity.
- The service proxy retains ordinary plugin-session RPC scope. A controller-specific RPC allow-list remains a possible distribution restriction; it grants no management authentication.

Wire permission presentation is independent of host authorization. Hello, resume, broadcasts and Hub status responses omit `command-centre.manage` unless the receiving socket advertises `command_centre_permission`. New clients filter unknown status permissions, so future additions do not reject the entire connection/status frame.
