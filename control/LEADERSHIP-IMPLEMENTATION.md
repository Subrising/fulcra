# Portable leadership implementation and verification

The implementation generalizes `resumeOrganization` into one shared transfer transaction. Leadership supplies exact source/destination/worker selection and a synchronous committed-record callback; the old handback uses the same observation, re-selection, token publication and commit path. The current native admission guard is unchanged. Source and destination manager locks plus affected session locks prevent concurrent controller assignments during preparation. Operator takeover changes the recorded generation and defeats re-selection. Native input to the incoming seat or a retained worker defeats admission through their current human barriers. The outgoing seat becomes human-owned; its retained conversation is not the incoming supervisor's input channel.

The additive `leadership_handoffs` table stores ownership handoff context and a unique wake UUID. Existing deliveries records the transition and native send separately. Existing supervisor inbox/acknowledge endpoints expose and consume handoffs, including through retained older MCP modules. Source worker rows move as a complete set, original creation provenance remains immutable, and a returning empty seat may retain its stale manager grant. Orphaned attached relationships and incomplete creation reservations refuse transfer explicitly.

The runtime runs leadership reconciliation before permission and worker-event dispatch. An exact completed native request receipt resolves a lost wake reply without taking over the new supervisor; current BOOT, human barrier, generation and latest prompt must match. A second native inspection after the receipt read checks intervening input. Inconclusive delivery stays unresolved and never repeats the message. Explicit abandonment revokes destination automation, while a late receipt can resolve delivery evidence without restoring revoked authority. Human takeover marks an unconsumed handoff superseded. All retained dispositions remain visible.

Verification so far is isolated, not installed acceptance. The existing 83 controller tests passed before the change. Tests now cover A→B→A with the same worker, unchanged origin and allowance, old manager credential rejection, existing inbox consumption, exact-set/generation/operator checks, orphaned relationships, lost reply with a later automatic completion wake, takeover before wake, transition recovery, explicit abandonment and failed credential publication. Real child-process SIGKILL cases cover token publication, authority commit, wake intent and native admission before reply; reopening the journal retains the committed authority and sends a queued wake once, while an uncertain intent is never resent. The retained native adapter state in these crash tests is a fixture, not a running provider.

An isolated consistent copy of the actual current journal was made with SQLite VACUUM INTO. Adding the leadership table preserved all 14 previous table schemas and row hashes, passed integrity_check and retained mode 0600. Measured table addition was 1.9 ms on this host. The prior installed manager-summary baseline used 20 sequential read-only calls: p95 0.921 ms, maximum 2.429 ms, two roles/two workers. Acceptance budgets: installed summary p95 below 50 ms for the current inventory; observed handoff receipt within 30 seconds while native sessions are idle, excluding model response/working time; history 1000 records maximum, at most 32 pending seats per runtime dispatch. These are declared budgets; installed post-change measurements remain owed.

The private plugin exposes only eligible empty human-owned destinations, explicit source/worker consequences, a scoped handoff, and separate ownership/delivery/consumption states. It preserves stable management request IDs across network uncertainty. Its listed state is a timestamped journal observation; runtime conversations remain the activity view.

Stop only the owned controller, preserve a verified journal backup, load the additive migration, reload the private plugin and exercise actual saved sessions. The full ADW gate and installed acceptance are not inferred from the tests or this document. Source consolidation with the memory/Book/navigation components and the remaining full-platform obligations are still outstanding.


Source-review corrections: all unconsumed source inbox events (including suspended or delivered-but-unread observations) and worker event faults now refuse transfer; evidence is not silently marooned with the outgoing owner. Both seats and destination candidates exclude any recorded worker reservation, including unattached creation. A transfer reserves its exact wake body in the deliveries journal inside the same authority transaction, with state reserved (displayed queued). Preflight and commit both require capacity for transition plus wake; other operations cannot consume the reserved slot. Only the matching current leadership record can release that reservation into a native send intent. Takeover cancels a still-reserved wake without dispatch. Restart and receipt recovery use the originally persisted text, never regenerate a message from a newer release. Confirmed refused/abandoned phone requests clear their retry identity, while unconfirmed responses retain it. Controller shutdown disables new leadership pumps before awaiting in-flight operations; a transfer completing during shutdown remains queued for restart. These fixes have targeted tests and require renewed source review before rollout.
