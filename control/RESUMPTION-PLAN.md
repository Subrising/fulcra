# Resume a saved organization explicitly

Problem: after phone takeover, the retained Claude supervisor and Codex worker are both human-owned generation3. Their old relationship is orphaned. Generic promotion refuses existing links; rotating a manager grant does not resume workers. This slice restores an explicitly selected saved relationship without creating sessions or sending model input.

The operator request contains a stable UUID, parent ID and expected generation, an explicit list of zero through six worker IDs/generations, and a reason. Canonicalize worker order. Require a recorded capable saved parent, its existing manager grant, original manager-created worker records, same task, unchanged human-owned idle sessions, no pending permissions or uncertain deliveries, and no different-parent event link. Reject duplicate workers, parent-as-worker, a parent itself linked as a worker, unfinished creations and stale input. Unselected workers stay uncontrolled.

Acquire the manager key first, then all selected session IDs in sorted order. Acquisition is synchronous and fail-fast; release every acquired key in finally, including partial acquisition. Human takeover remains independent and always wins. Existing phone sends/handbacks use these session locks; all sessions remain human throughout asynchronous preparation, so manager tools and event dispatch have no valid delegation to act on. No special unresolved-intent checks need to be scattered across those paths.

Use the existing deliveries ledger with kind resume. After validation/lock acquisition, store intent before async preparation. The identical duplicate returns its receipt; an unresolved intent is never replayed. Phase A captures each session's monotonic grantedAt BEFORE native inspection, then collects native identity, idle/pending state, event baseline and current task authority. Phase A changes no journal authority and writes no grant file. A failure leaves a refused receipt; a crash leaves an intent which explicit recovery marks refused without any delegation or prompt replay.

Phase B is one synchronous SQLite transaction with no awaits: re-read all expected human modes/generations and provenance, write every selected transfer and session authority field, rotate the parent grant, attach all selected event links with new epochs, preserve original creation evidence, mark old pending anchors reattached and old queued wakes suspended, and finish the resume delivery with exact transfer IDs/generations. Extract the existing synchronous transfer-row writes into an internal store primitive, reused by normal transfer and this transaction; do not call nested transactions. A crash before commit leaves all prior authority intact; after commit the whole selected organization is resumed. Human input arriving after an inspection still wins at native admission because stored grantedAt predates that inspection. Task-authority changes are checked again on subsequent manager sends as today.

The manager and inbox MCP processes already reread their fixed grant-file paths on every call. Prepare fresh token values in memory. During the synchronous commit section, write each token to an exclusive private temporary file, flush it, rename to the existing stable path and fsync its directory BEFORE committing SQLite. Every selected session remains human in other readers' committed view until SQLite commits, and controller RPC cannot interleave with the synchronous section. A file failure rolls back the database; a crash before commit may leave unreferenced private token files, which confer no authority and are safely replaced by a later explicit attempt. Do not delete or reconstruct another operation's tokens. This preserves existing native MCP processes without changing their configuration or restarting providers.

Preserve creation provenance losslessly without changing the installed native guard: add an append-only manager_origins table. Immediately before a worker's first reassociation, copy its original request, supervisor, creating epoch/generation, native request and body into that table inside the same transaction. Never overwrite that origin later. Existing manager_workers epoch/generation remain the current authority fields already consumed by the installed guard, owned() and summary(); update only those selected rows. Request/body/native identity and row count remain unchanged, so lifetime quota is unchanged. The delivered resume receipt records old/new authority and exact transfer IDs structurally, never in free-text tags. Test that origin values remain byte-identical across two resumptions.

Recovery of an unresolved resume receipt only finalizes a never-committed attempt as refused: no authority changes require cleanup. If the transaction committed, the receipt is already delivered. Extend controller recover/disposition to distinguish resume from native sends; manual handback text containing any apparent operation tag has no authority meaning. Keep the existing journal capacity bound. Recovery must take the same operation locks and preserve all newer human changes.

The phone panel shows saved parent/worker modes and generations, requires explicit worker checkboxes and a reason, and uses the existing fresh-health preflight and durable management identity. Success refreshes ownership cards; a new supervisor instruction is a separate action. An uncertain receipt offers reconciliation of the never-committed attempt, not blind Resume. Preserve urgent takeover and keep tokens out of browser replies.

Alternatives: recreating sessions loses continuity; generic regrant drops relationships; automatic adoption ignores human control; a second journal duplicates the existing ledger. The initial sequential handback/grant/attach proposal was rejected by independent challenge because it created partial authority and complex cleanup. Atomic validate-then-commit removes those states. An immutable origin copy plus the existing current-authority columns preserves guard compatibility, whereas moving current authority into new columns would require another native guard rollout.

Use the two retained phone sessions for an actual resume, one bounded supervisor follow-up, same-worker output and supervisor review, then human takeover. Preserve prior accepted artifacts unless a new instruction explicitly requests revision. Do not repeat completed acceptance tasks.
