# Completion watch recovery

AIN88 replaces new conversational background processes with an owned local queue service. A short-lived watcher with a JSON intent record could lose pre-dispatch tracking on process death. Per-receipt LaunchAgents would multiply installation and cleanup; a single private SQLite queue reuses the existing controller event wait and notification route. No worker execution, ownership, Gateway or provider configuration changes.

`watch` commits a deduplicated receipt to `conversation-queue/queue.sqlite` before returning. `ai.orca.watch` claims up to four receipts, waits once on existing controller events, and releases unresolved waits back to the queue. There are no model calls from idle polling. Ninety-second leases allow pre-dispatch recovery after service death. Compare-and-set transitions reject stale lease holders.

States: queued → waiting → queued (unresolved), or waiting → dispatch-intent → wake-submitted / needs-reconciliation. A committed dispatch intent is never reclaimed. A crash between that commit and notification may lose the wake; a crash after external delivery may lose its acknowledgment. Both remain visible and require reconciliation, because the external event API offers no atomic transaction with this database. No exactly-once delivery claim.

The `watches` action shows the latest 32 records and a service heartbeat. Inspect controller results and the originating isolated OpenClaw heartbeat history to reconcile an ambiguous intent. Do not delete records, resend assignments, or assume wake-submitted means the orchestrator read it. Legacy JSON watch records are retained and exclude the same receipt from new queueing. Queue metadata is private to the existing trusted OS user; this is not a new remote authentication boundary.

Rollout: install an immutable conversation release and only the `ai.orca.watch` LaunchAgent with mode077 umask, background priority and bounded restart throttle. The service reads existing installed Fulcra configuration. Rollback: boot out only this agent, restore the previous conversation symlink and skill, retain all queue bytes and manually reconcile queued receipts. Reboot, external-volume loss, physical phone delivery and independent Claude review are separate acceptance lanes. Do not interrupt unrelated services to test those scenarios.

Validation maps: queue tests exercise independent SQLite connections, dedup, stale leases, SIGKILL at waiting/dispatch intent, uncertain delivery and path controls; existing conversation/ingress tests retain takeover and receipt invariants. Installed idle restart is an operational test, not full-machine durability certification. Error logs and stale heartbeat are the operator's failure signals; no additional external notification channel is installed.
