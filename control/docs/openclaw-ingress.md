# OpenClaw scoped command ingress

## Outcome and scope

the owner can assign and inspect one explicitly delegated saved Fulcra session from a bound OpenClaw conversation. Preserve native identity, delivery IDs, takeover, canonical memory and the existing task journal. This command increment precedes durable completion wakes; neither is the full Fulcra release.

## Choice and existing responsibilities

Reuse capability-authorized controller inspect/send. Add a narrow capability-authorized result projection because existing inspect does not return response text. This is smaller in authority than OpenClaw calling the operator-authorized Paseo management RPC. No second controller, task board, worker copy, service, timer or database schema. No creation, takeover, role transfer or permission grants through ingress. OpenClaw remains a portable participant.

## Trusted origin and credential boundary

Use api.registerTool factories with the actual runtime OpenClawPluginToolContext, never the scaffold simple execute context. Require senderIsOwner strictly true and bind agentId, sessionKey, ephemeral sessionId, requesterSenderId and nativeChannelId. Channel mode requires nonempty sender/channel. Owner-session mode requires a trusted owner, absent channel/sender/messageChannel and either oneShotCliRun strictly true or an exact operator-configured trustedOwnerSessionKey. This fallback explicitly authorizes owner-attributed turns in that one saved session; it does not infer a physical human or local invocation from missing fields. Native Claude in OpenClaw 2026.9.2 drops oneShotCliRun in the plugin context, as observed in the retained diagnostic canary. Public ingress sanitizes senderIsOwner to false; all non-owner turns still refuse. Regenerated sessionId requires re-enrollment. Abort signals prevent use after a canceled owning call. Tool instances capture only the current run context and reread operator-owned binding every invocation and after awaits.

The boundary is the new ingress path, not OS isolation against the already trusted same-user shell. Existing OpenClaw main has unrestricted exec/filesystem access; this change does not claim to stop that shell reading existing secrets. New ingress never reads or returns operator.secret or Paseo controller.secret. Only an existing single-session grant is consumed. Initial acceptance uses a dedicated OpenClaw-owned local agent selected by required plugin agentId. A before_prompt_build toolsAllow hook narrows that agent to the three ingress tools through the native CLI exact-tool-availability path; other agents receive no hook change. Agent tools.allow alone filters the OpenClaw projection and is not assumed to remove native Claude builtins. Its effective allowlist contains only the three ingress tools; no exec/read/process/sessions_send/automation or other filesystem capability. Live Discord activation also requires owner-only channel routing. Broader host-hardening is not silently claimed or applied to existing agents.

An operator-written private binding references an exact existing grants/<sessionUUID>-<generation>.json. Validate all binding keys, origin/task/session UUIDs, positive generation, same-user regular nonsymlink files, restrictive mode and byte bounds. Tool arguments cannot choose paths, credentials, origin, task or target. The binding hash must remain unchanged across preflight. Revoke the native delegation before removing a binding for a control revocation: the controller rechecks that capability at dispatch. Removing a file alone cannot cancel already admitted work.

## Request and output states

No binding -> no control. Bound plus current delegated generation -> status or assignment. Native takeover, boot, task authority or input identity change -> existing controller refusal. A capability-scoped prepare-send RPC reuses the existing management_requests fingerprint over session ID, delegation generation and trimmed instruction. The plugin proposes a fresh host-generated UUID; the existing controller transaction returns the same durable UUID for identical instructions in that delegation, even when the OpenClaw MCP bridge gives retries different mcp-UUID call IDs. Model arguments cannot choose the ID or another target. Distinct text gets a different identity even if a provider reuses a short tool-call counter. Existing unresolved-delivery and busy admission still apply. Identical text deliberately reuses its prior identity until an operator acknowledges it through existing management controls or a new delegation generation is granted; use a distinct instruction for distinct work. Preparation has no native input; a lost preparation reply is safe to retry, resolving the same fingerprint. Return the confirmed prepared ID even on send transport failure and require status/result before another instruction. No provider-native or stable MCP call-ID assumption remains.

For newly admitted sends, retain generation, boot, native ID and pre-send timeline cursor in the existing delivery result through its acknowledged/uncertain/refused update. No old row is rewritten. Add controller result RPC with the same per-session capability: validate UUIDs; inspect current ownership; enforce current task authority; select only that session's delivery; require state delivered for a send with new cursor metadata and current matching generation/boot/native identity. Call existing native.completion/completionFor from that cursor, then inspect and recheck capability and identity after await. Return bounded outputPreview, truncation, ended, outputObserved, evidence hash and delivery identity; accepted remains false. Exclude internal progress, secrets, filesystem paths and unrelated row fields. Old deliveries missing cursor report unavailable, not guessed evidence. A changed or incomplete timeline refuses. The existing completion reader is bounded to ten pages/one MiB and 8192-character preview, and flags incomplete progress; ended is never independent acceptance.

## Verification and rollout

The isolated OpenClaw config explicitly grants this plugin hooks.allowConversationAccess=true and leaves allowPromptInjection enabled so its tool-restriction hook can run. Registration refuses before exposing tools if that grant is absent or prompt hooks are disabled. The hook returns only toolsAllow, never consumes conversation content or inserts prompt text. Verify loaded typedHooks and actual Claude --tools/--allowedTools/--setting-sources arguments; metadata listing alone is insufficient.
Scoped preparation stops at 128 total management requests, preserving the remaining capacity of the existing 1000-row table for operator actions. The limit includes confirmed deliveries and operator backlog: either can prevent new distinct ingress assignments at 128 total rows, so confirmed requests need periodic operator management-ack. Existing fingerprints still resolve at the limit. An operator can reclaim an unadmitted send with management-ack after its delegation generation has been revoked and no operation is in flight; current-generation preparations and unresolved deliveries cannot be discarded. This bounds refused-assignment accumulation without forgetting a possibly dispatched receipt.
Tests cover malformed/false/missing owner; wrong sender/channel/reset; nonprivate, symlink, oversized, changed binding; canceled signal; generation and native/task takeover before/during result; wrong delivery session; old missing cursor; controller response timeout; deterministic same-tool-call replay; unresolved-delivery refusal; output projection excluding secrets. Controller tests exercise actual capability and durable store; plugin tests exercise actual private files and fake transport only where identified.

Native canary: new dedicated saved session and dedicated owner-local OpenClaw agent with only ingress tools. Record actual trusted context and effective config hash, bind explicitly, invoke one real assignment, read actual native response, repeat same delivery through transport replay and prove no second input, revoke native delegation and binding then prove refusal. Existing human sessions remain untouched. Isolated plugin activation only after source review; no live Gateway restart or Discord post in this increment.

Controller deployment uses the existing external process owner and immutable bundle, with original journal/source/config backup and current integrity checks. This adds fields within existing delivery result JSON, with backward-compatible unavailable behavior and no SQL migration. Rollback revokes the new binding, disables plugin, restores prior source against the current journal and preserves all receipts; never restore an old database over new history. Test old source reading new result fields. Full ADW gate remains a separate enforced completion criterion.

Implementation refinements from reviews 9cf9348ee294 and bfa3d4c42ee1: the controller uses state delivered and retains outputContext in send, event-tracking refusal, recovery and abandonment. Local tools require the explicit owner-session conditions above; the dedicated agent has no inter-session, spawn, cron or heartbeat tool capability or scheduled bindings. The entry uses defineToolPlugin factory, which passes the actual toolContext to api.registerTool and supplies native authoring metadata. First-turn native identity may be absent at admission: after validated acknowledged input it can be attached to the receipt. If still absent, result conditionally persists the first validated observation before reading output, re-reads the winning identity and requires it stable around the read. Later reads must match the retained identity; its source is labeled retained-first-result-observation. This does not claim an ID existed before admission. Cancellation after dispatch returns the retained receipt with a cancellation note.
