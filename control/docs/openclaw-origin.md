# OpenClaw call and instruction origin boundaries

Ingress calls now require an active plugin service and a single-use permit matching the host's prepared run, saved conversation, tool-call ID and exact arguments. Supported call IDs are the observed claude-cli MCP bridge `mcp-UUID` form. Missing hooks, unknown triggers, expired or canceled runs, stopped services, replayed calls and changed arguments refuse. A user turn with queued plugin injections gains no ordinary-owner permit. Owner runs remain usable until run end/replacement, with a four-hour safety bound; wake tickets retain their three-minute bound. Literal `internal` channels refuse as a conservative check; OpenClaw uses `webchat` for internal routing, so that literal is not the provenance boundary. Before the model runs, the current-input hook requires the isolated patched host's versioned provenance snapshot: explicit `external_user`, `sourceChannel=orca`, `sourceTool=orca_operator`, current owner attribution and matching identity. Missing provenance, unknown versions, reports, internal-system recovery/replay and ACP/voice-shaped input cannot obtain owner permits. A prompt annotation can additionally deny, never grant. The hook revokes permits without blocking conversation or replacing transcript content. Tool visibility is not authority; execution still needs a gated exact call. Heartbeats retain their separately validated completion tickets. Owner-only configurations keep service and hooks active without starting the watcher.

The new `ingress-prepare`, `ingress-send` and `ingress-result` routes retain the binding-derived origin hash with the existing prepared request and delivery `outputContext`. One origin may use a session's delegation generation. Different origins cannot race to prepare or adopt its instruction; sending requires the exact prepared ID, text and origin. The controller repeats the checks after asynchronous preflight. Legacy direct, operator and manager APIs remain available, but their provenance-less receipts cannot enter the new origin-bound completion loop. No old receipt is backfilled.

Incoming manager or event links prevent ingress from controlling that worker, including a link attached after preparation. Outgoing links remain allowed: they describe a supervisor controlling its own workers and do not grant another writer access to that supervisor. Result and completion handling recheck origin, current generation and incoming links. Follow-ups retain the same origin and existing durable choice. Native takeover still invalidates delegation; uncertain admission and recovery preserve origin without resending an instruction. There is no SQL schema migration.

This implementation is undergoing delta review and isolated installed verification. It is not active in the main Gateway or Discord. `orca-ingress/host-patch.mjs` builds a separate copy of OpenClaw 2026.9.2 from the exact pinned runner hash and exports current `params.inputProvenance` to `before_agent_run`; it never infers provenance from absent metadata, current text or previous history. Other copied bytes are checked against upstream; the output manifest records the existing dependency symlink. The global installation remains unchanged. Supported owner entry is the trusted operator client's explicit-provenance Gateway `agent` RPC on an idle claude-cli session. This is producer assertion under existing admin trust, not physical human authorship or a new approval. Unpatched hosts, ordinary CLI/UI/Discord input without that provenance, and runner paths dropping it refuse owner control. Scoped completion recovery remains supported; arbitrary interrupted owner commands may need a fresh explicit owner turn.

Actual unpatched probes retained in runtime evidence observed an admin-attributed `internal_system` input reach unbound status, proving why the old annotation-only gate was insufficient. The patched-host installed checks are pending; source tests are not installed acceptance. A dedicated isolated launch must verify its host, plugin and profile bytes. Queued-owner and real interrupted-report recovery are separate lifecycle controls. The `--local` runner did not start the plugin service and is not supported. Gateway webchat factory matching remains exact, with no native channel/sender, plus the private conversation binding. No embedded-runtime steering or physical-phone claim is made.

Rollout uses immutable source, a consistent current-journal backup and controller-first activation followed by the isolated plugin. Rollback disables the plugin first and restores the previous controller against the current journal; never replace newer history with an old database. Keep legacy isolated completion profiles disabled when their receipts lack the new provenance.

The existing scoped preparation limit is 128 retained rows, including admitted rows, across scoped users. Repeated identical preparation reuses its ID at the cap; new distinct instructions refuse until an operator acknowledges older receipts. Acknowledgment removes that deduplication row. This known availability limit remains explicit pending the separate retention design.
