# Natural OpenClaw conversation — AIN-84

the owner wants ordinary conversation to operate persistent Fulcra work without typing slash commands or UUIDs. The existing main OpenClaw agent already has trusted local execution. The installed slash plugin registers commands only; the older isolated ingress plugin restricts its agent's tools and cannot replace main's normal tool surface.

Decision: a main-workspace skill plus a small local client. Reuse the existing controller, command-origin binding, receipt ledger and native sessions. No Gateway code/config/restart is required. The alternative of adding a new model tool plugin would need a new host-hook authority path and rollout; installing the old ingress unchanged would remove main's tools. Neither is necessary for this trusted same-user use case.

`orca-conversation/SKILL.md` maps owner outcomes to named saved sessions and declares the non-Claude exception to the older workspace Bridge instructions. `client.mjs` maps strict JSON actions to existing RPCs. Creation is Codex-only and task-authorized; retained task/title preparations reuse a creation receipt. Delegation persists the same private binding used by `/orca`. Sends, results and acknowledgments use per-session capabilities and origin-bound ingress. Background wait uses the controller's native event subscription, with its existing 20-second transport fallback and a one-hour overall bound. No repeated model polling is needed.

Trust boundary: this CLI has the existing OS user's operator authority. It does not authenticate a Discord speaker, and instructions in a skill are not a security sandbox. OpenClaw controls execution admission and owner attribution; the skill is installed only in main's workspace. Do not expose the client as an untrusted HTTP endpoint or advertise the CLI as a restricted-agent boundary. Private controller secrets are read only inside the process and never included in output.

States: created/saved human → observed → explicitly delegated → prepared → delivered or unconfirmed → output observed → reviewed as appropriate → acknowledged. Human takeover or native input changes invalidate the capability. A session cannot gain control merely by appearing in the catalogue. A lost send response retains its receipt; retries use existing controller deduplication. No automatic takeover, recovery, resumption or credential changes are added.

Live findings: the first real main OpenClaw canary created one saved Codex session and got ORCA_CHAT_READY_59. It resolved the original symlink entry problem itself; the client now explicitly resolves its entry path. Global `tools.exec.notifyOnExit` is false, so plain background wait cannot establish callback delivery. The `watch` action explicitly submits a native system event to the originating main conversation, with a durable at-most-once dispatch record. A crash/uncertain response is retained as needing reconciliation; another watch call cannot silently replay it. Background watch records do not grant worker control, and no global notify or heartbeat settings are changed.

Verification maps to the client contract: actual SQLite/RPC tests cover creation and send deduplication, native response loss, restart, wrong generations, malformed envelopes, private-file permissions, pending permission attention and takeover races. TypeScript checkJs checks the changed production module and its imports. The live acceptance must separately prove installed skill discovery, actual OpenClaw tool use, one native worker prompt, correlated output, completion wake behavior and final human ownership. Test doubles cannot establish those installed claims.

Rollout: copy the client and its unchanged source dependencies into an immutable versioned directory; atomically select it with a local `current` symlink; install the skill in main's workspace. Keep the live Gateway config hash and old slash package intact. Rollback removes the new skill and current link (or restores a prior client version), preserving session history and grants. Background wait is a process, not a restart-durable scheduler: if that process or Gateway is lost, use the retained receipt to reconnect. Completion event delivery must be observed before calling it unattended supervision.

Claude execution, cross-family review, native task import through the known watcher hang, phone pairing and social publication are outside this change. User authorization permits continuing and installing this non-Claude work; missing independent review remains explicit in the ADW ledger and release queue. The client is not a declaration that the whole Fulcra goal is complete.
