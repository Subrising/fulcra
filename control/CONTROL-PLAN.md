# Scoped session control

This implements slice 2 of ORGANIZATION-PLAN.md under AIN-73. Reuse the existing mini Paseo daemon for creation, turns and native history; Paperclip remains accountable task authority. A controller library and owned Unix socket hold only session enrollment, delegation generations and durable message delivery IDs. No second task board or memory database is introduced.

The first slice creates new independent sessions in fixed owned non-Git directories. It never enrolls existing finite-proof, book-peer, repair or human sessions. A person can explicitly create a human-owned or delegated session. Delegation returns a random capability scoped to the exact session and generation, retained only as a hash in the journal. Its model-facing client offers scoped inspect/send only; supervisor creation and additional lifecycle tools follow in the next slice. Human takeover revokes the generation immediately. Handback requires the current session idle and an explicit reason, preserving its native session and delivery history. Every delegated write re-reads Paperclip ancestry through AIN-73, open status and the local-board assignee; an outage refuses work. Same-user processes remain trusted: capabilities prevent accidental tool misuse, not an attacker with native shell/filesystem authority.

Persist an intent before create/send, then the received acknowledgment. An interrupted or failed network send remains uncertain and cannot be automatically replayed. A repeated ID with identical content returns the existing record; changed content is rejected. An unresolved intent blocks new sends to that session until explicit evidence-backed disposition. Human takeover can always revoke future writes, including during an in-flight send, but cannot retract already delivered input. UI/native user messages detected since the last attributed controller message revoke delegation. The human-facing result must make that distinction clear.

Use a fixed loopback Paperclip endpoint, bounded reads/timeouts, UUID task/session IDs, bounded prompt and message counts, and no credentials in logs. New session paths are computed from validated UUIDs under one owned root and checked for symlinks. The controller gets the existing Paseo credential at connection only and never puts it in provider environments. Creation has no parent/caller session, so worker lifetime is independent. Canonical memory is explicitly configured from the reviewed adapter. No automatic permission responses are added by this slice.

Before deployment: independent challenge, focused tests for authority outage, forged target, distinct/duplicate IDs, crash uncertainty, generation races, and current-user-message detection. Then real Claude and Codex create/send, same native ID after handback and controller restart, stale-token refusal and actual timeline correlation. Root controls only newly owned sessions. Later slices add model-initiated scoped session creation, event-driven supervisor follow-through, routine permission handling, phone controls, cross-host transport and delivery/decision traceability. These remain required by the full goal.

## Challenge resolutions

The operator is the user or an explicitly authorized orchestrator acting on the user’s management channel. Administrative RPCs require a distinct random operator credential stored mode0600 only in the owned control home; it is never supplied to sessions, MCP environments or prompts. Model-facing tools receive only a per-session capability through an owned client-side credential file; inspect and send both require that capability. Handback is absent from delegated tools and cannot be called with a session capability. A same-user shell can still read operator files; that is an explicit local trust limit, not a claimed OS boundary.

Paseo0.8 has no before-send plugin hook and its normal send may interrupt a running human turn. Client-side idle checks alone are insufficient. Before enabling delegated sends, install a narrowly reviewed guard at the existing daemon’s synchronous stream/replace admission points and prompt/steer entry points. The guard applies only to registry-enrolled orca-control sessions, rechecks the journal’s current generation, native last-user timestamp and absence of an active run before accepting a controller intent. Other human input unconditionally passes with no journal or filesystem access, and establishes a daemon-local time barrier. A grant must predate neither that barrier nor a daemon restart. The guard reads the journal only for prefixed controller intents; the controller remains its sole writer. Its next refusal/inspection records takeover. Labels do not bypass this check. Control ordering uses the host monotonic clock from process.hrtime.bigint, shared by daemon and controller, rather than wall time. A coincident clock value refuses automation until a later explicit handback. Native archive, close and stop entry points also establish the barrier before their asynchronous lifecycle queues. Archived sessions refuse handback and delegated sends, including before the product default-unarchive path. A saved closed session may resume only through explicit handback after a boot change or stop barrier; a stale grant cannot reopen it. The barrier map caps at10,000 distinct session IDs, after which automation refuses but human input continues. The exact released module hash is checked before applying the small hook patch, and guard code is pinned. No new provider or session manager is introduced. Native CLI resumes outside the managed host require explicit takeover; they are not represented as atomically observed by Paseo. A daemon restart that loses correlation fails closed and requests handback; a controller restart retains delivery IDs.

Use Paseo’s persisted message receipts and keyed create API where supported. A same-ID recovery probe is explicitly operator-triggered and can only acknowledge the existing receipt; uncertain messages are never automatically replayed. Bind delegation to the selected task’s authority tuple (company, assignee, parent and status), require it unchanged at send, reject blocked tasks, and cap the entire ancestry walk at four seconds. Native admission rechecks the current controller generation after asynchronous work. Restart acquires an OS advisory process lock, probes any existing socket, and removes a stale socket only after refusal and a matching inode check; a concurrent second controller refuses the lock. The guard, operator separation and recovery checks are prerequisites to real delegated control, not later optional improvements.

## Release and rollback

No live guard is installed yet. Preview uses exact pinned source hashes and native admission/lifecycle hooks, including the final lazy-iterator boundary immediately before provider startTurn. Prefix controller message IDs with orca-control: so journal absence can never turn controller input into human input. Normalize text with trim before journaling to match Paseo text-only prompts. Acknowledged messages remain delivered if subsequent observation fails; that failure revokes delegation. Definitive guard refusal is recorded separately from an uncertain acknowledgment.

Stop only this owned Paseo supervisor and daemon after its owned verification sessions are idle. Applying requires no6791 listener and no live owned supervisor, a clean explicit source commit, verified backups, and rolls back partial writes on error. Restart using the foundation's hardened launcher, which preserves the organization plugin. The loaded guard writes its random boot ID, actual process PID/start time and module hashes at import. Before connect/create/inspect/send, the adapter checks that this process is the actual6791 listener and that disk hashes match. A daemon restart invalidates existing grants and requires explicit idle handback. Confirm an actual stale controller intent is refused in a newly owned canary before enabling general delegation. Exercise Claude/Codex sends and the human race in live sessions, preserving native IDs and plugin functionality.

Rollback disables the owned controller first, stops only the owned Paseo service, runs deploy-admission.mjs --rollback to verify and restore all exact released modules from retained backups and retire activation receipts, then restarts the foundation and checks authentication, session IDs and the organization plugin. Do not remove the guard path while patched modules remain. Interrupted partial deployment is recoverable by the same hash-checked rollback command. Preserve journal, grants, session data and evidence. The patched foundation module hashes become an explicit new installation baseline; dependency audit hashes from the unpatched installation are historical.

Lifecycle coverage includes storage-only archiveSnapshot and the public cancel command before its idle/no-op shortcut; stop intent therefore revokes even if the turn finished just before the request was processed. The third pinned module is lifecycle-command.js; its change is only the guard import and command-entry call.

The native session interrupt entry also raises the same barrier before its idle shortcut, covering voice abort after a completed turn. Four exact released modules are pinned; the session module is adjacent to the agent directory and its preview/backup uses its basename under the same owned preview directory. No caller controls those static patch paths.
