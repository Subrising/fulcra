# Durable native events and supervisor follow-through

AIN-73, owned by this Codex task. Extend the existing sole-writer controller and SQLite journal with explicit worker-to-supervisor subscriptions, a bounded inbox, consumption acknowledgments and native snapshot observation. Paseo remains the session runtime; Paperclip remains task authority. No new daemon, board or generic message bus. This change does not answer permissions automatically: it preserves each distinct prompt for the next authorized handler.

The operator attaches a worker to an independently resumable supervisor, both already enrolled in the same task. Attachment records both control generations. Only currently delegated, unchanged generations can originate automated work or receive wakes. Human takeover suspends the link; explicit attachment after handback is required. Attachments never create or renew delegation. A session may supervise several workers, but each worker has one current supervisor. Self-links and cycles are refused. Role transfer changes the link epoch; queued old-epoch events remain inspectable and cannot wake the new owner automatically.

Before dispatching a linked worker instruction, the controller records its durable delivery ID, worker generation, link epoch, native boot/identity and pre-send timeline cursor in an additive pending-completion table. The runtime reads forward in canonical pages, saving its cursor and bounded output tail/hash chain after each pass. Large turns continue across passes instead of repeatedly searching backward or faulting because of total output size. The exact prefixed user-message ID anchors the turn. A later input or stable idle tail ends it without establishing success or acceptance. Complete turns missed during a connection/process gap are recoverable from these records. Epoch/identity drift, absent anchors or capacity failure suspend the link visibly; transient transport errors retry on the next runtime pass. Revoked and reattached anchors remain explicitly unresolved, and definitely refused input is marked not-delivered. No status edge or attention badge determines correctness.

Every reconciliation probes the worker through the existing controller identity check, then rechecks after native evidence reads. A human-originated input records takeover and prevents automated event dispatch even if the journal generation was initially unchanged. Events are tied to the original controller delivery; each pending permission includes its native ID plus canonical request hash. Different IDs or changed contents remain distinct. The event loop never grants permission itself. Native subscriptions reduce latency; a30-second runtime-only watchdog reconciles at most32 links, without waking a model to scan history.

An idle delegated supervisor receives one concise notification for the oldest eligible inbox event, using that event's stable UUID as its native delivery identity. The notification contains only server-generated IDs and kind, and tells the supervisor to inspect and acknowledge all available inbox observations. Worker text appears only as explicitly untrusted evidence in the inbox. Busy recipients wait; already consumed events skip dispatch. The existing controller journals and guards the send with the recorded supervisor generation; admitted ambiguity never produces a fresh identity or blind retry. Delivery and consumption stay distinct. Wakes stop once the shared lifetime delivery count reaches500, reserving half of its1,000 slots for manual management. This is a visible capacity limit, not a complete long-term retention solution.

The supervisor gains inbox and acknowledge MCP tools through an inbox-only random credential, hashed in the journal and tied to its current control generation. Its file is outside task artifacts, in the controller's grants/inbox directory. This token cannot authorize native sends or ordinary session inspection. The tools record consumption with a short evidence/next-action note; acknowledgment does not certify output acceptance. Existing single-worker assignment tools remain supported; expanding creation/multiworker management is a subsequent bounded change. Attachment requires an idle worker before the next instruction, rather than silently missing a turn already in flight.

Acceptance: duplicate event suppression across process reopen; two distinct permission events retained; no cold-idle completion; human takeover and changed authority suspend wakes; busy supervisor later receives queued event; dispatch ambiguity keeps one delivery ID; stale link events stay visible but do not wake; native actual worker turn triggers an independent supervisor that reads and acknowledges the event, inspects an actual output and writes a review. Source tests supplement this real interaction. No existing repair/human session is enrolled.

Rollout is an additive table migration with a consistent SQLite backup while the sole writer is stopped. Prior controller ignores new tables. Stopping the event loop restores manual phone/native use without deleting sessions, inbox evidence or delivery receipts. Bound live links to32, retained events to1000; capacity exhaustion is explicit and does not discard uncertainty. The long-term retention/archival policy remains a separate requirement before larger operation.

The native guard exposes a read-only observation of its existing in-memory human-input barrier through an overwritten reserved label in the authenticated fetch-agent response. It adds no filesystem work to human input. Controller inspection compares that timestamp with delegation time, so a human stop/close/voice abort is detected even when no user-message identity changed. This extends the existing four-module patch and requires its reviewed apply/rollback/restart path. Stale user-editable labels are overwritten by the native response. Wake dispatch selects one oldest eligible event per supervisor, so a busy recipient does not starve another, and receipt recovery refreshes inbox delivery state without replay.

Paseo's native caller/parent finish notification was considered and rejected for this ownership path: it is not durable and its unprefixed steer input would be treated as human activity by the installed guard. Controller creation sets neither callerAgentId nor parent labels. Adding a separate message bus would duplicate the existing controller's identity and journal; deriving correctness solely from subscription edges would lose work across gaps. A bounded native-evidence reconcile is the smaller reliable option.
