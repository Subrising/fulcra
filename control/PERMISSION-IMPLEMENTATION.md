# Permission delivery map and threat record

Requirement 1 maps to `permissions.mjs` (explicit grants, shared reservation count, durable distinct intents, no retry after uncertainty), `permission-policy.mjs` (owned files and exact edits), `admission-guard.mjs` (read-only native authority checks and per-boot one-shot set), and `permission-result.mjs` (current tool correlation). The observer verifies previous tools before handling another request; normal verification waits suppress model wakes. The native patch also raises the human barrier at sendPromptToAgent entry, before its first await, and at the central permission response boundary.

Requirement 2 maps to the existing private plugin's strict management schema, authenticated server bridge, grant/revoke buttons, shared remaining count and recent result states. Grants are operator-only; supervisor workers inherit an existing current root pool. Session generation or parent ownership drift invalidates it. Existing workers do not silently inherit a new grant. The controller's records are saved observations; native runtime remains separately visible.

Requirement 3 maps to `permission-overlay.py`, its pinned `permission-base.json` and the revised dependency switch. Preparation binds current guard-patched module bytes, both active manifests, immutable backups, both fingerprints and captured process identities. Apply/recovery requires the dependency lock and stopped-process check. Unknown bytes refuse; original dependency rollback requires overlay rollback first. Guard-only base rollback preserves the native takeover guard. Current homes, session data, secrets, plugin route repair and canonical memory paths are not rollback inputs. Old release directories remain because saved MCP configurations reference them.

Threats exercised: duplicate or changed native request; stale worker, parent, root-grant or boot; direct human permission response before admission; altered exact response/input; lost acknowledgment and controller restart; path traversal, hidden components, symbolic/hard links, oversized or unknown tool input, and post-approval path changes. The controller reserves quota before dispatch and stays the sole journal writer. A read-only guard works while the controller holds the WAL write lock. Post-write verification detects races but cannot undo an already executed same-user filesystem write. A process with arbitrary same-user shell access remains trusted, as in the existing platform.

Operational limits: one unverified response per root pool; 100 attempted responses per root grant; 32 grants and 1,000 permission records per journal; unknown tools escalate; a missed event is covered by the existing 30-second watchdog. Verification failure/deadline revokes the root and emits an incident. The UI reports the handler's latest error and pending/uncertain states. Native restart requires explicit handback/new grants. Retention, general provider approvals and cross-host role transfer remain full-goal work. No physical-phone or installed-acceptance claim is made by source tests.

Source validation lives under this worktree's ignored `runtime/permission-*` files: controller and policy tests, plugin TypeScript/build tests, dependency switch tests, and overlay recovery tests. Overlay tests kill real fixture processes at ten durable boundaries and recover both directions; they verify active module hashes, guard file and dependency fingerprint agreement and retain the guard on rollback. Actual installed acceptance must additionally verify the loaded native receipt, saved session identities, two actual prompts/resumed tool results and independent output review. An acknowledged response, a file hash alone or a completed test suite is not that acceptance.

Review corrections: native.mjs uses the released DaemonClient correlated waiter rather than the fire-and-forget agent API. The session overlay emits a marked receipt after the actual provider response handler returns; original-request-ID human or provider events cannot acknowledge an Fulcra intent. Controller and native guard compare the released wire projection, including removed empty metadata. Tests exercise the actual installed SDK waiter and projection. Uncertain intents are verified and deadlined alongside acknowledged ones, never replayed; exact tool evidence can unblock the pool. Worker inheritance errors preserve the already-created worker and expose missing authority. A full journal explicitly suspends routine handling in status. Installed root package/lock checks now cover overlay preparation and both recovery directions. Retention remains a separate requirement.

The controller registers persistent permission-resolution event interest before connecting and waits for the connection subscription acknowledgment before any permission response. Reconnect clears readiness and the SDK restores that interest. The regression test uses the actual SDK subscription manager, transport serialization and waiters, with an event-gated fixture response. Final verified/incident rows retain the preceding response evidence so a native acknowledgment remains distinct from later tool verification.
