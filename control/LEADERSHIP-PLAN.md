# Portable leadership, first installed slice

Transfer a quiescent saved organization from one supervisor to another provider on the mini. Keep every worker's native session, directory, output and creation provenance. The destination is an empty supervisor-capable saved session in the same task. This is a change of accountable owner, followed by a separately evidenced context delivery and consumption. It does not accept earlier work.

## Boundary and alternatives

Reuse the controller journal, current read-only native admission guard, manager grants, event links, canonical memory and private phone interface. Generalize the existing resumption transaction with a destination seat; keep one shared observation, re-selection, credential publication and commit path for handback and leadership transfer. Starting a replacement worker would lose the continuity being tested. Making OpenClaw permanently authoritative would contradict portable roles. A new cross-host controller is unnecessary for this first proof; existing Book peer transport remains a separate component to extend and verify later.

An operator supplies a stable request UUID, source and destination IDs with expected generations, the complete source worker set with generations, destination allowance (1–6, at least the worker count), and a 12–8000-character scoped handoff. Context contains outcome, current evidence/output paths, unresolved decisions and next action. Same-user processes remain trusted. This API is operator-only; an agent cannot silently move its own authority.

## Atomic ownership transition

Lock both manager seats and all affected sessions using existing controller locks. Require source to be a recorded supervisor, destination to be a capable empty human-owned seat, no worker role on either seat, and exactly the source's completed saved worker relationships. Empty means zero manager_workers rows and zero outgoing event_links, not absence of an old manager_grants row. A returning seat may retain its stale grant row; the transaction replaces it after confirming the seat is human-owned. Unresolved historical reservations are retained and explicitly refuse transfer until separately reconciled; they are never silently ignored, reassigned or used to reset lifetime quota. All transferred source worker rows move together, so the old seat has no worker reservations after transfer. Abandoned reservations with a durable native disposition can remain in a separate immutable history record once their reconciliation is implemented; that archival feature is not silently invented by this transfer. Source and workers may be human or delegated but must match their expected generation. Reject pending/uncertain deliveries, unresolved worker creation, pending permission verification, unresolved worker events and native busy/permission/archive states. Inspect every native session, owned cwd, task labels, BOOT and human-input barrier. Re-read journal state inside the transaction. A newer operator takeover cannot be overwritten.

In one synchronous journal transaction: revoke source to human, rotate destination and worker generations, issue destination manager/inbox credentials, update current worker ownership and event-link epochs/baselines, suspend obsolete queued notifications, preserve immutable origins, and append a leadership record with a unique wake UUID. Publish credential files before commit using the existing durable token-file pattern; an uncommitted token has no matching authority in the journal. On failed commit no partial owner is valid. Routine permission grants do not transfer: changed generations invalidate them and the UI requires a fresh explicit grant.

The existing native guard checks these dynamic grants, epochs and human barriers at dispatch. No native module overlay or Paseo restart is planned. A late native human input still defeats automation even if it arrives after controller inspection.

## Context delivery and recovery

A bounded additive leadership_handoffs table records source, destination, generations, worker IDs, context, wake ID, delivery state and an explicit consumption note. Existing deliveries separately records the operator transition and the native wake. The runtime pump uses the saved wake UUID exactly once through Controller.send under the new destination generation. Persist the transition and reserve the exact wake body/slot in the same transaction before any native send. A reserved wake is displayed as queued, becomes an intent only under its current leadership record, and is cancelled unsent on takeover. Check capacity before admission and again before commit; reserved capacity remains available even when other work fills the remaining budget. Restart examines existing wake receipts; it never blindly retries an intent or uncertain send. Dedicated transition recovery treats an intent without a committed leadership row as refused without changing any authority; a committed row returns its committed receipt. Both recover and disposition route this transition kind explicitly. Dedicated wake reconciliation requires the exact native receipt fingerprint, wake ID, same BOOT, current destination generation, unchanged human barrier and exact latest native prompt identity. A completed matching native request receipt marks the wake delivered and updates expected/expectedAt without takeover. Receipt completion is native request completion, not finished agent work. Inspect/reconcile must run this leadership reconciliation before generic unexpected-input detection and before queued worker-event dispatch. While the latest prompt is the known wake but its receipt remains inconclusive, preserve the current delegated generation and hold further supervisor sends; never treat that known uncertain wake as an unrelated human input. Any actual human barrier, BOOT or generation change still wins. A receipt arriving after such revocation may resolve delivery evidence but never restore authority. Known pre-dispatch busy states wait cheaply; revoked authority suspends the wake. Native send acknowledgment means delivered, not consumed. The destination reads handoffs through the existing supervisor_inbox tool and acknowledges the handoff ID through supervisor_acknowledge, then inspects existing workers and actual outputs. These existing scoped endpoints also work through retained older MCP modules; no old immutable bundle is changed. Handoffs remain in their separate journal table, never fake worker event links. Consumption does not mean work was accepted.

Keep old credential/module paths and handoff/event history. Repeating an identical operator request returns its original result; changed input with the same ID refuses. A new leadership transfer must not overtake an unconsumed prior handoff targeting a still-current destination generation or any unresolved wake. Handoff terminal states are consumed, superseded-by-takeover, and operator-abandoned. Controller takeover atomically marks unconsumed handoffs for the revoked generation superseded, while preserving their separate delivery evidence. Native barrier/BOOT detection uses that same takeover path. An operator may abandon an inactive uncertain wake with an evidence note; this marks the handoff operator-abandoned, revokes destination automation, preserves worker ownership rows, and never retries input. Reconcile an exact completed receipt or explicitly abandon uncertainty before the next transfer. The next handoff includes predecessor IDs and dispositions automatically. Unconsumed handoffs are returned ahead of ordinary event history in supervisor_inbox, in a separate handoffs array, so old suspended events cannot hide them. Bound retained handoffs at 1000 and expose capacity refusal. Worker allowance accounts for the inherited workers; handoff does not duplicate reservations or reset their provenance.

## Interface and installed proof

The existing private phone page offers a source/destination choice, context and an explicit summary of affected workers, revoked source authority and permission-grant consequences. It shows transferred, queued/delivered/uncertain/suspended and consumed separately. Native conversations remain directly reachable. Verify at 390, 768 and 1440 pixels and retain actual UI evidence.

Create one new human-owned first-class Codex supervisor. Transfer the existing Claude phone supervisor's organization to it, keeping the existing Codex worker and its saved outputs. The incoming supervisor reads canonical memory, acknowledges the context, inspects and assigns that same worker, and completes a useful revision/review loop with automatic event wakes. If a second-family reviewer is needed, authorize capacity two and let it create a saved Claude worker. Verify actual native timelines, worker IDs, artifact hashes, corrections and independent acceptance. Then demonstrate transfer back or explicit human takeover without replay. Neither a test stub nor a queued handoff counts as installed acceptance.

## Verification and release

Tests cover exact-set validation, stale generations, operator authorization, busy/uncertain states, human input races, parent/worker token invalidation, immutable origins, event deduplication, preserved worker identities, one-shot wake delivery, consumed acknowledgment, restart and lost replies. Kill a real isolated process before/after authority commit and native intent; reopen the journal and prove one owner/no repeated input. Verify additive migration against a copy of current journal rows and schemas. Measure transition/wake latency and bounded table behavior against the current controller baseline.

Rollout: independently review frozen source; stop only the owned controller while every enrolled native session is idle and human-owned; make a verified journal backup; prepare an immutable controller bundle with unchanged admission-guard hash; start, verify loaded service identity and additive migration; reload the private plugin; run the actual canary. Rollback first puts affected seats/workers under human control and reconciles any native wake. Stop the controller and restore the prior controller/plugin paths while retaining the expanded journal and all native history. The old controller ignores the additive table; never restore old session history. Radius NO LAUNCH/NO TEARDOWN and existing repair/Gateway ownership remain unchanged.

This slice is not cross-host leadership, general task creation, broad provider permission authority, automatic startup, or full-platform completion. Those remain required work. Source/installed review acceptance is distinct from the complete ADW stage verdict.

Challenge resolution: tests additionally cover a lost wake reply followed by exact receipt recovery and a later automatic worker-completion wake with destination authority retained; inconclusive receipts holding events without resend; transition-intent recovery before commit; takeover before consumption followed by a clean A→B→A transfer; and a stale grant on an empty returning seat. A seat with an unresolved historical reservation refuses with an explicit reason rather than silently losing that reservation. Capture current manager and event-link rows in installed preflight.
