# Fulcra owner commands

This native Discord command uses the existing controller and a private, explicit binding to one saved session. It creates no model session, scheduler, worker or external notification. Normal command replies return through Discord as ephemeral responses. Set the base Discord slashCommand.ephemeral option explicitly true; a selected-account false override or missing setting refuses at service start and on every command. Discord remains an external processor for input and reply content.

Use `/orca sessions [page]` to list eight saved sessions at a time, with task IDs, journal ownership and generation. This does not inspect live activity or grant control. `/orca delegate <session UUID> <generation>` explicitly hands the chosen idle session to this exact Discord origin, subject to the existing controller task-authority check. The generation prevents a stale command from replacing a newer owner. `/orca ask <instruction>` generates a receipt ID for you. Also available: `/orca status`, `/orca send <request UUID> <instruction>`, `/orca result <receipt UUID>` and `/orca ack <receipt UUID>`. The complete command must fit 4096 UTF-8 bytes. Identical retained instructions deduplicate, including repeated `ask` commands; an ID is not a Discord interaction identity. Acknowledgment permits a deliberate repeat while retaining delivery history; it implies neither completion nor acceptance.

The workspace helper uses the existing local operator credential only for listing and explicit handback. Instruction dispatch retains its narrow session capability. It writes a private grant, the existing ingress binding format, then an atomic private selection pointer; reconnect uses that pointer without changing the plugin configuration. Concurrent commands refuse while one resolves. A service/selection change during an await prevents further dispatch. A crash or binding failure after handback can leave an unreachable delegation: no instruction is sent, no automatic handback retry or broad takeover runs, and the refusal tells you to inspect the current generation. Recover through app takeover or an explicit new delegate command at the observed generation. Switching sessions leaves prior sessions in their existing modes; revoke them in the app when desired.

Configure the exact Discord account, guild channel, owner sender, saved session UUID and absolute private `bindingsDir`. DMs, threads, non-owner senders and Gateway admin route claims refuse. The origin hash is SHA256 of JSON with ordered keys `accountId,conversationId,provider,senderId,sessionId`, with provider `discord`. Use the existing private binding/grant format from `orca-ingress`, in a separate command-only directory. Another origin requires explicit delegation; never copy a wake binding or manufacture authority.

Install from a reviewed immutable release containing this package and its sibling `orca-ingress/src/relay.mjs` and `controller-client.mjs`; do not copy the command package alone. Discovery requires OpenClaw's normal restart. Main activation needs an external-owned rollout/rollback and a real Discord owner command/reply check. Registry fixtures establish adapter behavior, not actual Discord origin or physical-phone operation. Service stop and binding replacement invalidate in-flight command authority.

Account privacy overrides are checked across all case-variant account keys. After any reply-privacy configuration change, wait for the Discord channel restart to complete, then verify that `/orca help` is private before requesting session data. The provider captures reply visibility at monitor start; the handler sees the latest config snapshot, so it cannot itself certify visibility during a hot-reload transition.
