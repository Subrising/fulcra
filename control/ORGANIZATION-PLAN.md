Owner: Codex task 00000000-0000-4000-8000-000000000000, Paperclip AIN-73. This continues the owner authorized full goal. It uses the existing pinned Paseo 0.8.0 hosts, AIN company, Paperclip board and ADW. It does not take over existing Bridge/repair sessions or release Radius holds.

## Decision and impact

Use a local Paseo plugin for the organization surface and lifecycle hooks. Paseo already supplies a host picker, desktop/browser/mobile React Native surfaces, typed plugin RPC, session creation and persistence, and events for turn start/end and each permission request. Existing Paperclip remains authoritative for task accountability. The plugin projects observed runtime facts beside that task state. The alternative of a separate web dashboard would duplicate host authentication, mobile navigation and session views; using only freeform Discord messages would leave ownership, decisions and evidence hard to inspect. This is the previously selected architecture A, implemented through the product's supported extension surface.

Impact radius: one reviewed local plugin in the owned mini Paseo home initially, later the same plugin on the owned book host; new Fulcra-labelled sessions and AIN-73 descendants only. Plugin code is trusted same-user code with native filesystem/network access. No public listener, new manager, credential copying, global provider-setting replacement, Gateway restart, or general control over discovered human sessions. Initial global pluginsEnabled is absent/false and no plugins are registered. Enabling the owned plugin is a distinct deployment step after source/type checks and review; source creation does not enable it.

## State and permission contract

A task can be queued, submitted, consumed, running, waiting for a distinct permission/help/dependency, interrupted, output-produced, independently accepted, delivered and live-verified. Every promotion needs the corresponding observed event or artifact check. Provider turn IDs can repeat after reopening; include native session/opening and client message identity, never turnId alone. Restart reconstructs from native timeline and durable intents; missing correlation remains uncertain.

Every permission identity includes host, session, exact request ID, tool name and canonicalized input. Two different prompts stay distinct even if the tool/path is identical. Auto-response is limited to exact actions already within the task's delegated authority and approved artifact paths, with symlink/escape checks. Shell escalation, changed scope, vision/design/cross-system decisions and unknown requests remain visible for an authorized decision; they are not blindly allowed. Journal intent must be durable before response and acknowledgment durable afterward. Uncertain delivery is reconciled or explicitly abandoned with evidence, never cleared by deleting state.

Human-facing decisions show current situation, concrete alternatives, impact/dependencies, expected change, uncertainty, recommendation, selected authority and examples. Execution authority, decision authority and what the owner should understand remain separate. Routine low-consequence work should proceed frequently without repetitive approvals. Leadership hats change the questions emphasized, not the factual state or permission boundary.

Observation resource contract: Paperclip uses the existing implicit local-board identity over a fixed loopback GET endpoint, with no cookie, copied credential, daemon env secret or redirect. Local API write authority is a same-user residual; absence of writes is enforced by this code, not a read-only OS/API capability. The issue response is capped at 128 KiB and four seconds; session list is capped at 100, refreshed Fulcra snapshots at 32 with an eight-second total budget and three seconds per call. Four explicitly fixed synthetic files are each capped at 64 KiB for hashing. A server reader coalesces concurrent viewers and caches one observation for 30 seconds, retaining its original timestamp. The client refreshes every 30 seconds while foregrounded, offers manual refresh, and marks observations over 60 seconds or failed refreshes stale. Two clients in a simulated five-minute test cause at most ten underlying reads. Session membership is explicitly label-based/unverified in the UI.
