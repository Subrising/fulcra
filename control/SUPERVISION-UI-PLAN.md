# Phone supervision roles and saved ownership

Extend the installed private Fulcra management panel with explicit supervisor delegation and a saved view of its workers. Keep native conversations, the Paperclip outcome and the controller journal as the existing sources of runtime, task and ownership information.

The controller owns promotion. It validates the complete request, unchanged human-owned generation, absence of existing supervisor/worker links and a delivered creation receipt recording manager tools before transferring control. Mutable native labels do not establish capability. Already delegated sessions cannot use promotion to rotate authority. Existing links require a later explicit reassociation operation. A grant failure compensates by returning the just-transferred generation to human control, unless a newer transfer already won. Responses expose no capabilities. A lost response is reconciled through saved state, not an automatic retry.

The public summary contains bounded supervisor and worker identities, saved ownership, allowance/reservations, latest event delivery and consumption, and unresolved creation/fault state. The plugin filters to its enrolled task, validates the returned schema and renders no tokens, payloads or arbitrary file paths. Saved ownership does not establish current native activity or independent output acceptance. Workers and supervisors open their existing native conversations.

The mobile panel supports 390px and wide light/dark views. A bounded read-only health request traverses browser-to-Paseo and Paseo-to-controller. Failed transport and returned controller errors have distinct messages; cached cards show their saved observation time and stale status. A fresh health round trip precedes each non-urgent mutation. If that check fails, no mutation is sent. A failed response after invocation remains explicitly uncertain. Human takeover retains an independent path during other requests. Health leases bound connection detection; instantaneous transport awareness is not claimed.

Acceptance: use the actual private browser at 390px to create a capable supervisor, delegate a bounded allowance, assign an outcome and see its model-created worker. Open native conversations, take control, observe suspended/orphaned ownership and reload without losing saved state. Exercise browser WebSocket closure separately from controller socket unavailability, verifying stale cards and unavailable role controls. Do not treat browser offline emulation alone as proof that an established socket disconnected. Physical phone interaction remains unobserved unless actually performed.

Alternatives: a separate dashboard duplicates navigation and state; browser-held capabilities enlarge authority exposure; plugin-owned role transfer splits authority logic. The chosen controller-owned operation reuses the current private host and sole-writer journal. Blast radius is selected mini sessions, additive role metadata and this plugin. Other hosts, Gateway, provider authentication and Radius holds are unaffected. General permission policy, worker reassociation, cross-host control and artifact discovery beyond the existing published list are separate increments.

Rollout: stage an immutable reviewed controller, confirm the admission guard bytes are unchanged, switch the sole controller under its existing lock, then reload the plugin. Verify one chosen session before broader use. Rollback restores the previous immutable controller and plugin source while preserving additive records and saved sessions. No daemon restart is needed when the guard bytes are unchanged.
