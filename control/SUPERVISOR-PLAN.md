# Portable task-scoped supervisor controls

## Outcome and choice
An explicitly delegated Claude or Codex supervisor can create persistent first-class workers, discover its owned workers, assign or revise work, inspect durable progress and receive the existing event-driven review wake. Use the current controller, journal and MCP interface instead of installing another manager or passing the operator secret into models. This bounded increment is local-mini control; cross-host transport, permission policy, UI role editing and general task acceptance are separate increments. No provider credentials move.

## Authority and state
The operator grants a delegated supervisor management authority with its current generation, task authority, an explicit reason and a lifetime worker limit (1–6). A separate random manager token is stored hashed in SQLite and provided through a fixed grant file outside task artifacts. Inbox tokens, ordinary worker tokens and manager tokens are not interchangeable. Models cannot mint grants, adopt existing workers or restore human-owned sessions.

Creation reserves a unique model request ID and body under the manager, then generates and persists a separate random native request UUID server-side before calling existing idempotent native create. Initial native directory creation is exclusive; an existing directory refuses. The returned session must have the exact owned cwd/labels and an empty timeline. Link reservations and wake capacity are checked before creation. A reservation counts against its supervisor lifetime limit even if native creation is uncertain; only current-epoch reservations under a still-delegated manager count against global reserved link capacity; changed bodies and collisions with unrelated delivery IDs refuse. The created session is enrolled human-owned first. Automatic delegation is allowed only for that manager's newly created, untouched generation-1 idle session with no native prompt, human barrier or permissions. After any native receipt recovery, the exact cwd, labels and empty error-free timeline are verified again before automatic delegation. After delegation the exact generation is recorded and the same-task event link is attached before any work instruction. Crashes or takeover at an ambiguous boundary retain an inspectable reservation/session and require explicit operator recovery; no guessed replay, human-session adoption or replacement session.

A worker has one manager reservation owner, keyed to its grant epoch, and one generation-bound event link. Supervisor takeover or grant rotation makes prior workers orphaned and refuses further assignment even after a new grant; no silent adoption occurs. An already running worker may finish, and its native session is retained. Explicit per-worker reassociation is a later operator operation. A crash after automatic delegation may leave an unlinked delegated worker without an exposed token; its reservation remains visible and requires operator recovery. The supervisor can list its reservations, inspect its own currently linked workers and assign using the existing delivery-ID protocol. Repeated assignment IDs return the existing receipt and changed bodies refuse. An ended turn and inbox acknowledgment are not acceptance. Outputs are evidence for the supervisor's review and follow-up tools.

## Human takeover and native admission
Both supervisor and worker are inspected before privileged operations. Every manager send binds supervisor generation, manager grant epoch, worker generation and event-link epoch into durable intent. The native admission guard verifies those bindings against SQLite and both sessions' in-memory human-input barriers at the actual worker dispatch boundary. Therefore a supervisor takeover between authorization and native send refuses the send even before the controller has noticed it. Human input itself retains the existing zero-I/O path. Grant rotation invalidates old manager intents. An already accepted worker turn may finish after supervisor takeover, but no new manager instruction is admitted. New empty session creation may finish after takeover; it is retained human-owned without sending work.

## Interfaces and trust
Operator manager-grant accepts sessionId, expectedGeneration, capability, maxWorkers and reason. Manager MCP exposes manager_workers, manager_create_worker, manager_inspect_worker and manager_assign_worker; its caller session is fixed by the grant file, never a model-supplied principal. The grant does not authorize external publication, permission responses, task reassignment, arbitrary native control or another supervisor's workers. Files and sockets remain in the existing trusted same-user macOS boundary, not an OS sandbox against malicious same-user shells. Strict request keys, UUIDs, text bounds, at most 32 manager grants and existing journal/link caps apply. Manager-created workers get the same portable tools but no manager grant, so the supported MCP path provides no recursive grant. Same-user shell access can read other grant files and impersonate their holder; the runtime does not claim to isolate a malicious same-user worker or authenticate which model invoked a socket request.

## Rollout and verification
Source tests cover wrong tokens, task changes, quotas, repeated create/send IDs, changed bodies, uncertain creation, human interruption before/after creation, ownership isolation and exact native parent-barrier rejection. Use a reviewed four-module admission patch with actual original-hash rollback/reapply and loaded receipt verification, then start the sole controller after all enrolled sessions are idle. The new daemon boot revokes previous delegations; only chosen acceptance sessions are explicitly handed back, attached and granted after restart. The chosen supervisor must be newly created with the updated supervisor MCP configuration; old saved MCP paths are not silently rewritten. Preserve journal backup and additive manager tables. The controller socket must be listening before recovered event wakes are dispatched.

Supervisor instructions must enter through the management panel/controller send or event wakes; typing directly into the native conversation intentionally takes human control and revokes manager authority. Live acceptance: an explicitly granted Claude or Codex supervisor uses MCP to create one worker from the other provider family, assign an editable non-Git artifact, receive its event, inspect/review it and request a correction in the same native worker. Record actual native IDs, tool calls, output hashes and independent review. Prove a human takeover prevents a further manager assignment without restoring control. Existing native sessions and memory stay available. Rollback stops the owned controller, restores the events admission patch and starts source3f048ac with retained journal; no worker/session teardown. Bounds and ambiguous creation remain visible instead of silently retrying.
