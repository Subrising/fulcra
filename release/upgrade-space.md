# Existing Mac upgrade space

Compilation continues to use `package.sh` with its 9 GiB system and 25 GiB staging-volume floors. On Book, `SPACE_VOLUME` points at Book's internal staging filesystem. Upgrade preparation never compiles on Mini.

`upgrade_space.py` replaces the historical upgrade's unconditional `/Volumes/mac >= 25 GiB` check with destination-specific additional allocations plus reserves. Its checks run before receive, before stage writes, and again before stopping services or swapping the app. A refusal exits 75 and changes no service. Callers retain the device map from preflight and refuse a changed mount. The existing 9 GiB system-volume reserve remains. Metadata-only volumes retain 1 GiB beyond a bounded 64 MiB attempt budget; the upgrade adapter must cap its backup/roster/log output to that budget. It never copies or restores chat history.

Measure each bundle's logical file bytes, allocated blocks and entry count. A full-copy bound is `max(logical, allocated) + 4096 * entries`; this charges sparse/compressed files by logical size and adds allocation/metadata slack. Give APFS clones no space credit. Before receiving, budget four simultaneous candidate allocations: incoming artifact, immutable release, installed-app temporary copy, and a retained full failed-clone/ditto partial. After receive, the incoming bytes already reduce observed free space, so stage checks charge the remaining three. The GUI installer uses one `ditto` copy, without a second clone attempt. A failed attempt remains owned evidence; any retry gets a fresh preflight against the remaining actual capacity.

Reserve another 16 MiB on the release volume for the seal module, manifests and service profiles. `sealBundle` hashes files in memory and does not unpack `app.asar`; its selected scratch contains the copied seal module only. No archive, extracted runtime dependency tree or compilation cache is produced in the live upgrade. If that procedure changes, update the model before executing it.

Retained installed bytes are reported separately. App replacement and its rollback path must share a filesystem: rename the old app into the fresh rollback path, then rename the verified installer temporary app into place. The old allocation remains occupied; it does not need a second copy. Refuse an existing rollback destination. Never replace user profiles, daemon homes, accounts or newer journals during rollback.

The receive footprint comes from the immutable build-host artifact. Re-measure the received local bundle and verify its full bundle seal before staging. After the immutable release copy, use the `installer` phase to recheck the remaining temporary-app allocation against freshly observed space; use `cutover` only when both copies exist. Guard checks are capacity checks, not integrity or quiescence approval. The upgrade adapter must recheck capacity immediately before each owned write and before service changes, verify selected process lifetimes are idle, use graceful shutdown, and verify the installed byte identity and retained state afterward.

The initial Mini baseline measured candidate13 at 548,409,550 logical bytes, 550,404,096 allocated bytes, 983 entries: a 554,430,464-byte independent-copy bound. Stage therefore needs 1,680,068,608 additional bytes on the internal app/release filesystem plus the retained 9 GiB reserve. Receive needs one more copy bound. The external metadata destination needs 64 MiB plus 1 GiB reserve. These are baseline estimates; new candidate bytes and actual filesystem availability determine the final requirement. Report an exact shortfall to parent for reversible movement of confirmed inactive owned artifacts. Do not delete other work or lower a floor silently.

Run `python3 -m unittest discover -s release -p upgrade_space_test.py -v`. Tests exercise refusal before a service-action callback, fresh capacity at cutover, real staged copies and rollback, a real filesystem probe, full sparse-file/fallback bounds, changed mounts, destination links and rollback overwrite refusal. Successful fixture cutover is an isolated rehearsal, not live installed acceptance.
