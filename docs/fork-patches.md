# Fork patch ledger

Fulcra is a deliberate fork of Paseo. Its core changes are grouped into a few named patches so each upstream merge conflicts in predictable places. The orchestration core (hierarchy, durable report-up, re-parent/promote, account pool and credentials, permission veto/admission, session launch) stays in core as named patches; it cannot be a plugin. Separable UI views, usage sources, and lifecycle observation policy move to bundled plugins. Nothing here is offered upstream.

Every file that differs from the Paseo base is listed with its patch in [fork-patches.tsv](fork-patches.tsv). `node scripts/fork-ledger.mjs --check` fails when that list is stale; regenerate with `--write` and review the change. Mark owned seams in core with `// FULCRA(<patch>)`.

How attribution works: a file whose path names a patch belongs to it; tests follow the file they test; otherwise each diff hunk is attributed by its content keywords and the file goes to the patch with most changed lines. Files where no patch has 60% are listed as shared seams. Attribution is heuristic: move a file by adding a path rule in `scripts/fork-ledger.mjs`, not by editing the TSV.

## Merging upstream

1. Merge the upstream tag with ancestry in a worktree (`git merge <tag>`), never by copying source.
2. Resolve conflicts patch by patch, in this order: `build-ci`, `branding`, `core-fixes` (drop fixes upstream now has), `durability`, `pairing`, `plugin-host`, `accounts`, `session-launch`, `admission`, `orchestration`, `features`. Resolve the shared seams last, hunk by hunk.
3. Update the pinned upstream commit in `scripts/fork-ledger.mjs`. Regenerate the ledger and check each changed attribution.

## Upstream watcher

The daily watcher runs at 05:17 UTC. It opens one review PR for each new stable tag, including intermediate tags.
Paseo uses the package version on `origin/main` as its baseline. Other upstreams use [the watch manifest](../.github/upstream-watch.json).

For a manual intake PR, include a marker for each covered tag, such as `<!-- upstream-watch:paseo:v0.11.4 -->`.
The watcher checks open and closed PRs before it writes. A failed PR lookup stops that upstream.
A pushed `sync/*` branch without a PR can be retried. These branches belong to the watcher.

Dispatch `upstream-watch.yml` with `dry_run=true` and `only=paseo` to check an intake branch.
The dry run reads that branch with a read-only token. It fetches public tags but creates no commits, branches, or PRs.
The write job always reads trusted `main`. It does not run upstream npm code with its write token.

Repository Settings → Actions → General must permit Actions to create pull requests.
Job-level `pull-requests: write` cannot override a disabled repository setting.
GitHub combines PR creation and approval in this setting; an owner must enable it.
If creation is refused, the job reports the pushed branch and the manual PR link.

## What stays in core and why

Decided 7 Oct 2026 after the Paseo v0.11 merge: a piece moves into the bundled plugin only when that costs less than the shared-file lines it removes. Measured against v0.11.0-beta.5, the self-contained features are new files (no merge conflicts) whose hooks into Paseo files are small:

| Feature | Hooks in Paseo files | Cost to move | Decision |
| --- | --- | --- | --- |
| Automations | ~150 lines, 14 files | 2 SDK seams (schedules, server-side API) + ~900-line UI rewrite | Stays: own patch `automations` |
| Architecture map | ~167 lines, 20 files | ~8.4k-line UI rewrite + git/PR data in the plugin | Stays in `features` |
| Insights | ~58 lines, 11 files | recorder as plugin events + UI rewrite | Stays in `features` |
| Limit resume | guarded host handoff and private queue writer | native event observer in the bundled policy resource | Parsing and timers move; admission stays in `accounts` |
| Report-up | private finish ownership, reporting lines, and held delivery | native lifecycle observer and notice policy | Observation moves; dispatch stays in `orchestration` |
| Portable memory | none (already in `control/`) | n/a | Unchanged |

Organisation, hierarchy, account controls, and switching live in the Command Centre plugin. Native Usage owns quota presentation.
