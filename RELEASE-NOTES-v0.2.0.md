# Fulcra v0.2.0 — release candidate

This unsigned macOS arm64 candidate is produced from the consolidated source `01eaec63c52a7754b26bf4b6fafd99e8c55eac6f` (tree `5ee9b606906b7dde8f68914bb60e2ebb30f3522c`). Installed acceptance on both Macs and final publication approval are pending. Later optional native Radius changes are outside this artifact.

The candidate includes Command Centre accounts and usage views, session hierarchy and project ownership controls, owner-scoped report/output metadata, explicit content-grant controls, the operator queue, Git draft previews, catalog paging, and the Fulcra orchestration skill. The Git preview uses the host's default Claude account and requires workspace write permission; suggestions fill editable text and do not commit, create a pull request, or resolve files automatically. Subject drafts are limited to 72 characters.

New top-level Codex sessions default to `full-access` unless an explicit session, role, Settings or configuration choice overrides it; internal helpers retain conservative modes. **Codex Full Access runs commands without approval prompts. Fulcra cannot pre-check credential access, destructive Git actions or publishing in this mode.** The owner accepted this limitation (L52) for v0.2.0 native Codex FullAccess only, conditional on release-note and Settings disclosure. It does not exempt Claude, host-sync grants or future releases. Claude approval gates and separate host-sync authorization remain required; no Codex pre-execution enforcement is claimed.

Owner operations keep registered identity, epoch, scope and original connection/lifetime checks. Schema availability, status and labels grant no action or content authority. Queued, provider-accepted, consumed and human completion remain distinct states; uncertain attempts are not replayed automatically. Project demotion reparents children upward, and project transfer retains the old owner's read scope until the host permits narrowing. Multi-owner ambiguity refuses rather than guessing ownership.

Radius persistent saved runs remain default-off. The native Bicep validation module is **not included in v0.2.0**; it is absent from this artifact and public tree. The view separates local planning, scratch simulation, compilation and deployment; simulation does not prove native compilation. Native validation was separately tested with a host-provisioned Darwin arm64 Bicep 0.46.1 toolchain and Radius 0.61 types; this toolchain is not bundled for user installations. Its finite sandbox probes do not establish universal same-user isolation. Real environment launch, deployment, teardown and contact remain held. No release operation enables Radius or grants destructive pruning permission.

The actual desktop runtime is Electron 44.2.0, embedded Node 24.20.0, arm64 ABI 149/N-API 10. The shipped pty, msgpackr and sherpa modules loaded in that runtime without starting a terminal, model or provider. Sharp/libvips and the SDK's vendor ripgrep/tree-sitter binaries are absent from this desktop membership. CLI/provider availability still depends on supported user-installed tools and the installed smoke results.
